# 01. 项目结构、manifest 与模块化

## 最小目录

```text
MyScript/
├─ manifest.json
└─ main.js
```

`manifest.json` 与 `main` 文件必需为 UTF-8。

## manifest.json

当前源码识别以下字段：

```json
{
  "manifest_version": 1,
  "name": "示例脚本",
  "version": "1.0.0",
  "bgi_version": "0.0.0",
  "description": "示例",
  "authors": [{"name": "author", "link": ""}],
  "main": "main.js",
  "settings_ui": "settings.json",
  "scripts": [],
  "library": [".", "src"],
  "saved_files": ["data/*.json"],
  "http_allowed_urls": ["https://example.com/*"]
}
```

校验时 `name`、`version`、`main` 必填，且 `main` 指向的文件必须存在。

## main.js

普通脚本推荐：

```js
(async function () {
    log.info("脚本启动，BetterGI {0}", getVersion());
    await sleep(500);
})();
```

## ES Module

引擎支持标准 `import` / `export`，不支持 CommonJS `require()`。当 `library` 非空，或入口代码包含 `import` / `export` 时，会按模块执行。

```js
// src/util.js
export function clamp(v, min, max) {
    return Math.max(min, Math.min(max, v));
}
```

```js
// main.js
import { clamp } from "./src/util.js";
log.info("{0}", clamp(10, 0, 5));
```

不建议再用旧文档中的 `eval(file.readTextSync(...))` 模拟模块系统。它会污染作用域、弱化错误定位，并容易与 `const` / `let` 作用域产生混淆。

## settings.json

配置文件根节点必须是数组。常见类型包括：`input-text`、`select`、`checkbox`、`multi-checkbox`、`separator`。

```json
[
  {"name":"teamName","type":"input-text","label":"队伍名称","default":""},
  {"name":"enabled","type":"checkbox","label":"启用","default":true}
]
```

在调度器配置组中运行时，`settings` 会注入为配置对象。脚本修改字段后，任务结束时 BetterGI 会尝试保存回配置组。

```js
settings.lastRunAt = new Date().toISOString();
```
